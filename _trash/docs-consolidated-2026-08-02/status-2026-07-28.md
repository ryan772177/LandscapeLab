## 2. The move fork — full text

### Finding

> Moving an `ALandscape` via `set_actor_location` is NOT safe in a World
> Partition level, and this level is WP. Proxies are aligned to the parent
> only by `ALandscape::PostEditMove(bFinished)` →
> `ULandscapeInfo::FixupProxiesTransform(true)`
> (`LandscapeEdit.cpp:5138-5147`), which sets each proxy to
> `FTransform(FVector(SectionBase)) * LandscapeTM`
> (`Landscape.cpp:6154-6174`). `PostEditMove` is fired by the editor's
> interactive move tools; Python's `set_actor_location`
> (`K2_SetActorLocation` → `AActor::SetActorLocation`) never calls it. Since
> this level's components all live on proxies, the script as submitted would
> have moved the empty parent actor to the origin, left all 64 components at
> −403200, saved that torn state — and `verify_landscape.py` would then have
> PASSed the location field, because it reads only the parent's location. The
> tripwire was blind to exactly the failure its companion script could cause.

### Option (i) — delete and recreate by hand

Delete the landscape in-editor and recreate it once from
`landscape_spec.py`'s corrected printout, which now prints dialog Location
`403200, 403200, 0` rather than `0, 0, 0`.

- **Cost:** one manual redo.
- **Risk:** lowest. It uses the engine's own placement path — the only path
  that fires `FixupProxiesTransform` — and stays consistent with route B's
  "create by hand once, then verify" contract.
- Recommended by both the auditor and the main agent. **Never previously
  ruled on.**

### Option (ii) — proxy-aware mover

Extend `apply_landscape_transform.py` to set each proxy absolutely to
`recipe_origin + scale · section_base`.

- **Cost:** reimplements `FixupProxiesTransform` in Python; larger surface;
  needs its own audit.
- **Risk:** higher. Hand-rolling engine-internal invariants is the mechanism
  by which torn state arises in the first place.

being the stray.

## 6. WARNING: proxy labels are NOT unique — do not delete by label

The census's per-owner listing produced a checklist that **must not be used as
a label-matching list**. Four labels appear under *both* landscapes:

```
LandscapeStreamingProxy_1_1_0
LandscapeStreamingProxy_1_2_0
LandscapeStreamingProxy_2_1_0
LandscapeStreamingProxy_2_2_0
```

Proxy labels are auto-generated from World Partition **grid coordinates**
(`_<x>_<y>_<z>`), so two landscapes occupying overlapping grid cells produce
identical labels. `Landscape_Alpine`'s 4 loaded proxies sit at cells (1,1),
(1,2), (2,1), (2,2) — all of which `Landscape` also occupies.

**Consequence:** deleting by searching the Outliner for a label would delete
the wrong landscape's proxies. Delete via the **Outliner hierarchy** instead —
select the parent `Landscape` actor and delete it together with its nested
proxies, so ownership rather than name decides what goes.

The listing remains useful as a *count* and as evidence of ownership; it is not
safe as a name-matching checklist, and the script should be extended to print
`get_path_name()` (globally unique) before it is ever used that way again.

### Confirmed: `Landscape_Alpine` is the real import
Scale 800/800/500 matches the recipe exactly, and the measured component
spacing of **126 quads = 63 × 2** is the recipe's `section_size` ×
`sections_per_component`. `Landscape` has default scale 100/100/100 and a 2017
geometry that appears nowhere in the recipe.

### `Landscape_Alpine` is only PARTIALLY LOADED
Its `implied resolution 505` is **not** a contradiction — it is the World
Partition caveat firing. An 8×8 grid has section bases at
`0, 126, 252, 378, 504, 630, 756, 882`. The census sees only
`252, 378, 504, 630` — the middle 4×4 — so 4 proxies and 16 of 64 components
are resident. The outer ring is unloaded.

`Landscape` at scale 100 spans only 2016 m and sits entirely inside the loaded
region, which is why it reports complete while the 8064 m landscape does not.

**Consequence: all World Partition regions must be loaded before any verify
run is meaningful.** Otherwise the geometry check fails on residency rather
than on correctness.

### D3 is ANSWERED, and it fired
`num_subsections`, `subsection_size_quads`, and `component_size_quads` are
**all refused by the engine** — UE 5.8's `get_editor_property` will not read
bare `UPROPERTY()` fields. `landscape_guid` is likewise unreadable. Only the
`BlueprintReadOnly` fields (`section_base_x`/`_y`) and `EditAnywhere`
(`landscape_actor_ref`) came back.

This is the permanently-red-tripwire case: `verify_landscape.py` currently
treats unread fields as INCOMPLETE and exits 6, so it will fail forever on
those three rows even after the duplicate is deleted and the regions are
loaded. **Needs a ruling — see the D3 options in the audit log.**

The measured spacing does still pin the geometry: 126 factorises uniquely over
the dialog-legal sets ({7,15,31,63,127,255} × {1,2} → 7, 14, 15, 30, 31, 62,
63, 126, 127, 254, 255, 510, all distinct), so a spacing of 126 can only mean
63 × 2 among configurations the dialog can produce.

`ALandscape` derives from `ALandscapeProxy`, which is why the details panel's
"Landscape Proxy Count 65" exceeds the 64 streaming proxies the Python probe
attributed to it: the parent counts itself.
