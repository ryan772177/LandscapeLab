## CONSULT 2 — 2026-08-19 ~13:50Z — THE IDENTITY ARM FAILED AFTER THE BODY CORRECTION

**Position:** body diagnosed and corrected (`Masculine/Feminine` -1.0 -> -2.0 on

**My interpretation (0.85):** the body parameter changes the parametric face, and
the whole-rig import discards that adaptation by applying the DNA exactly.

**RULING: the interpretation is half right, and the half I was confident about
was the wrong half.**

- **Body -> face coupling: SUPPORTED.** The graded ratio profile (jaw 1.167 >
  cheek 1.108 > temple 1.096) is what masculinisation looks like, and
  `fit_face_state_from_body_with_eyes_teeth_dna` is the mechanism's name written
  into the API. **Under doctrine that name matters: when the body changes, a
  FITTER AUTHORS THE FACE STATE, and the identity arm refused to treat a fit
  product as identity. It was right to.**
- **"The import returns the face to canonical proportions": REFUTED**, using my
  own recorded numbers, which I had not compared.
- **Do NOT re-export a new canonical DNA from the current character.** That
  routes a fit product into the anchor: **fitters are verifiers, not authors, and
  re-exporting launders a fit into ground truth.** It would also destroy the
  identity arm permanently — a canonical exported from state X identity-passes
  at state X by construction and can never detect drift again.
- **Re-specify the identity criterion, do not loosen it.** What whole-rig import
  guarantees is DNA-DETERMINISM: same DNA + same body => same render, within
  floor. So the primary gate becomes IMPORT-TWICE REPRODUCIBILITY; the
  pre-vs-post delta is demoted to an advisory measurement of body-authored face
  adaptation. **A gate that can never pass on a class of input is not guarding
  that class, it is blind to it.**
- **Discard the in-memory import by closing without saving — but take one free
  reproduce-gated measurement first**, because the state is about to be
  destroyed and it is the cheapest evidence available.
